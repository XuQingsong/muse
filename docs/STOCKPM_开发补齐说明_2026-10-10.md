## 3. 精确选股细则（指认代码位置，不另立口径）

- **入场时机全部锚点**：`paper_trade_2026.py::compute_books` 内 timing_items 之前五组子分——趋势结构=三项 interp 均值：price_vs_ma200 [(-15,5),(-5,30),(0,55),(5,75),(15,90)]、ma50_vs_ma200 [(-10,5),(-3,30),(0,55),(3,75),(10,90)]、ma200_slope20 [(-2,10),(-0.5,35),(0,55),(0.5,75),(2,90)]；动量=mom3 [(-20,5),(-10,25),(0,50),(10,70),(25,85),(50,90)] 与 mom6 [(-30,5),(-15,25),(0,50),(15,70),(40,85),(80,90)] 均值；量能=vol_ratio [(0.5,25),(0.8,45),(1.0,60),(1.2,75),(1.8,85)] 与 up_share [(35,10),(45,35),(50,55),(55,70),(65,90)] 均值；入场位置=dev50 [(-15,25),(-8,45),(-3,75),(0,85),(3,80),(8,55),(15,25),(25,5)] 与 rsi [(20,35),(30,55),(45,75),(60,70),(70,45),(80,18),(90,5)] 均值；风险=vol20 [(20,90),(35,70),(50,50),(70,25),(100,5)] 与 drawdown252 [(-60,20),(-40,35),(-25,50),(-10,70),(0,85)] 均值。子分权重 趋势结构 35/动量 20/量能 15/入场位置 20/波动回撤 10。
- **动态分层**：`paper_trade_v18_full30.py::assign_tier`——质量或成长为 null 返回 None；(vol20>55) 或 (净利润与自由现金流同为负) 或 (营收增速>35 且估值<45) → 进攻；(vol20<30 且 FCF>0 且 FCF 率>5% 且 质量≥70 且 成长≥45 且 营收增速≥0 或缺失) → 防守；其余 → 普通。
- **成长确定性**：同文件 `growth_certainty`——成长分 ≥85 得 2 分（≥72 得 1）；营收增速 ≥30% 得 2（≥18% 得 1）；加速度 ≥3pp 得 1（≤-8pp 得 -1）；EPS 增速 ≥20% 得 1（<0 得 -1）；总分 ≥4 高、≥2 中、否则低。
- **基本面持有分六项**（同文件 `fund_hold_score`，六项最高分合计 90，代码直接 `return sc`，没有归一到 100；门槛 ≥45/≥55 都是相对 90 分制）：单季营收同比（≥20→15, ≥10→12, ≥0→8, ≥-5→4, 否则 0）+ 营收加速度（≥0→15, ≥-10→10, ≥-20→5, 否则 0）+ 毛利率变化（≥0→15, ≥-3→10, ≥-6→5）+ 现金流/净利润转换（≥1→20, ≥0.5→15, ≥0→8）+ 净负债/FCF（≤0→15, ≤3→12, ≤5→8）+ 流动比率（≥1.5→10, ≥1→7, ≥0.8→4）；缺失项按代码给保底分（8 或 5），网页展示建议原样引用。
- **负 FCF 现金门卫**：`today_plan.py::latest_signal` 内——进攻层且 fcf_ttm<0 时，须 营收增速 ≥30% 且 现金 ≥1.5×|FCF| 才 entry_pass。
- **PE>80 增速不匹配**：`compute_books` 红线——PE>80 且 (营收增速<15 或 加速度<-10pp) → "等价格"。
- **趋势破位**：三条件 **AND**——price_vs_ma200<0 且 ma50_vs_ma200<0 且 mom6<-10%。
- **拆股嫌疑**：(PE<5 且 PS<2) 或 (PS<3 且 毛利率>60) → 估值账整账作废（null）。
- **缺失/负值处理**：PE 仅在 EPS_TTM>0 时计算（compute_books 开头），负 PE 不进入估值；PEG 近似仅在营收增速>0 时计算；interp(None) 子项剔除、该账权重重归一；整账全缺 → 该账 null → 当日不可买；EPS/营收增速为负按各锚点区间正常落到低分段，不做特殊截断。

## 4. 规则差异核对（与交接文档不一致处以此为准）

- **距 MA50>+15%**：是**首笔减半**（today_plan 与 v18 一致，字段 half_due_to_dev50），不是排除。排除是另一条：**RSI(14)>80 且 dev50>+15%** 同时成立 → caps 含"不追高" → overheat=True → 盘前过滤剔除。PLTR 2026-10-09 实测：四本账 90.6/81.3/17.3/67.7、entry_pass=true、**overheat=true**、dev50_pct=18.1（附件 today_plan_2026-10-10.json 的 all.PLTR 可查），即两条件同满被剔，不是单看 18.1%。
- **VIX 恐慌闸门**：**仅 v18 回测**（paper_trade_v18_full30.py 第 157–166 行 _load_vix_fear、390/403/416/502/508 行使用）；**paper_tracker 前向未启用**，交接文档里只是背景保留——网页若展示 VIX 状态须标"回测规则，前向未启用"。
- **进攻 -40% 灾难止损**：**仅 v18 回测**（同文件第 457 行，自持仓高点回撤 ≥40% 且跌破 200 日线，且不受 VIX 闸门阻挡）；**paper_tracker 前向未启用**。前向的硬线只有第 4 节三层止损（自成本价）。
- **持仓层级变化**：止损/止盈线在建仓时按当时层与成本价锁定写入 state（stop_price/take_price），之后即使日度重算出的层变了也**不改线、不改层**。
- **止盈卖 1/3 取整**：paper_tracker.py 第 464 行——qty=max(1, shares//3)（shares>1 时），即向下取整且至少 1 股；卖后 take_profit_done=true，止盈只触发一次。
- **先止盈后同日触止损**：仍清剩余。结算按分钟逐根推进，止盈后持仓保留，若后续分钟触止损线则 stop_loss_sell_all 卖出全部剩余（take_profit_done 不挡止损）。
- **同分钟双碰推断**：`_bar_event()`（paper_tracker.py 第 377 行）逐根 K 线判定：开盘已越线先按开盘价；同一根内双碰时，收盘≥开盘按"先低后高"→先止损，收盘<开盘按"先高后低"→先止盈；reason 字段会写明"双碰：…"。1 分钟线为主，无分钟线退化日线同逻辑（标 daily_only）。
- **同日新买**：买入成交那根 K 线不判其止损/止盈（entry_timestamp 守卫，第 452 行起），从下一根分钟线起纳入。
- **成本 0.1%/边**：前向账本计入——买入现金扣 shares×价×1.001，卖出入账 ×0.999；初始 10 只入账未倒扣买入成本（文档已注）。交接文档 3.4 节"每边 0.1%"与此一致。

## 7. 更正与确认（2026-10-10 晚，逐条核对代码后）

1. **持有分上限是 90，不是 100**：`fund_hold_score` 六项最高 15+15+15+20+15+10=90，第 109 行直接 `return sc`，无归一。文档凡写"满分 100/（0–100）"处均更正为 90 分制；门槛 fund_score≥45（全层）、≥55（防守）不变。
2. **"只观察"与"等价格"不独立阻止新开（设计≠代码）**：`compute_books` 的 `excluded` 只认 caps 中的"排除"（趋势破位与两条基本面死亡）；流动比率<0.8 的"只观察"、PE>80 且增速不匹配的"等价格"只写进 caps/redlines 作提示，`entry_pass` 不查这两项，paper_tracker.premarket 也只额外过滤 overheat。**现状：这两条是提示，不是拦截**；只要四本账过分层门槛、现金门卫过、未触发"排除/过热"，仍可生成买单。网页若要显示，应标"提示（不拦截）"，不要画成否决。
3. **层间预算借用是现行真实规则，文档漏写**：`today_plan.py::buy_limit`（第 67–73 行，v18 回测同逻辑）——当组合已投资比例 <85% 时，防守/普通层的可买上限 = 本层预算带宽上限 + 进攻层未用预算的 75%。paper_tracker.premarket 用的就是这个函数。以此为准，PDF/交接文档的"层预算只限本层"表述不完整。
4. **分层波动输入与重算频率，口径明确如下**：`assign_tier(vol20, ...)` 参数名是遗留命名；回测信号路径（paper_trade_v18_full30.py 第 210–212 行）与前向 latest_signal 实际传入的都是 **60 日年化波动 v60**，仅当 v60 为 NaN 时回退 20 日波动。回测中 tier 只在**新财报状态到达时**重算（cur_tier 其余日子沿用）；前向盘前扫描对候选**每日按最新收盘重算 tier**，但 paper_tracker 已持仓锁定建仓时的 tier 与 stop/take 价线，不随日度重算变动。网页展示持仓层时用 state 里的锁定值，展示候选层时用当日扫描值，两者可能不同，属正常。
5. **跨环境同步：待开发（现状无自动通道）**：自动产物（paper_live/state.json、reports/）写在 Muse 沙箱 `~/workspace/quant-practice/`；用户 Mac 的 quant-practice 是 10/8 版，**没有 paper_tracker.py 与 paper_live/**。stock-pm 若在 Mac 或其他环境运行，目前**没有**已实现的自动同步：可用渠道只有聊天附件/下载链接（人工、链接会过期）。两条待开发路径供选：(a) 在 Mac 解压 2026-10-10 新代码包后本地跑 paper_tracker（包内含 paper_tracker.py 与 paper_live/state.json 种子），产物天然在本地；(b) 给沙箱侧加一个导出/推送任务把 state 与 reports 定时发到约定位置。在 (a)/(b) 落地前，stock-pm 请按"人工投递文件"对接，不要假设能实时读到沙箱文件。
